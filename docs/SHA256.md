# SHA-256 byte identity

`sha256.c/.h` supply a one-shot, allocation-free SHA-256 primitive for exact byte
identity. Tokenizer loading uses it on the owned ModelProto bytes before
publishing an immutable model.

```c
#include "sha256.h"

unsigned char digest[32];
int status = nt_sha256(data, bytes, digest);
```

Success returns zero and writes 32 digest bytes. Invalid input returns -1 and
leaves the digest unchanged. NULL input is valid for an empty message; output
must be non-NULL. The byte count must fit the standard's 64-bit bit length.
Input may be unaligned, and digest output may overlap input because all input
is consumed before publication. Scratch lives on the call's stack, with no
shared mutable state. Static and shared NoTorch libraries include the primitive;
`make install` installs its header.

The implementation follows the SHA-256 equations in
[FIPS 180-4](https://csrc.nist.gov/pubs/fips/180-4/upd1/final), sections 4.1.2,
4.2.2, and 6.2. No external hashing package is required.

```sh
make check_sha256
python3 tests/reference_sha256.py --output tests/sha256_reference.h
```

The native gate passes 545 checks on Linux x86_64 / GCC 13.3, including the
`abc` and 56-byte message in the
[NIST SHA-256 examples](https://csrc.nist.gov/CSRC/media/Projects/Cryptographic-Standards-and-Guidelines/documents/examples/SHA256.pdf),
the million-`a` vector from [RFC 6234 §8.5](https://www.rfc-editor.org/rfc/rfc6234.html#section-8.5),
the empty digest, overlap, invalid-input preservation, and 264 independent
Python `hashlib` fixtures. Their binary input covers every length from 0 through
256 and larger cases through one million bytes, exercising both padding paths
and unaligned reads. The committed C fixtures run without Python. Regeneration
is byte-identical; ASan/UBSan pass with `ASAN_OPTIONS=detect_leaks=0`.
